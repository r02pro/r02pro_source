# Contributing to R Programming: Zero to Pro

Thank you for helping improve this book! Every merged contribution earns you a permanent spot in the book's [Acknowledgment section](https://r02pro.github.io/acknowledgement.html). If you are enrolled in GPH-GU 2182 at NYU, merged pull requests and accepted issues also earn extra credit; see your course syllabus for details.

## Before you submit anything

**Search first.** Check the [open and closed pull requests](https://github.com/r02pro/r02pro_source/pulls?q=is%3Apr) and [issues](https://github.com/r02pro/r02pro_source/issues?q=is%3Aissue) to make sure nobody has already reported the same problem. The first submission wins; duplicates are closed without credit.

**Verify it yourself.** Only report problems you have personally confirmed in the published book at [r02pro.github.io](https://r02pro.github.io/). If the problem involves code, run the code and confirm the output. Bulk submissions that were clearly not verified by a human will be closed.

## Fixing something yourself: pull requests

Best for typos, grammar, code errors, and small wording fixes.

1. On any page of the [published book](https://r02pro.github.io/), click the **edit button** (pencil icon) in the toolbar. This opens the corresponding `.Rmd` source file on GitHub.
2. GitHub will prompt you to **fork** the repository to your account. Accept.
3. Make your edit in the web editor. Please keep each pull request focused on **one section** of the book.
4. Click **Propose changes**, then **Create pull request**. Fill in the template.

You can also fork and clone the repository and edit locally if you prefer.

## Reporting something you cannot fix: issues

Best for confusing explanations, incorrect output, broken code, missing steps, or suggestions for new content.

1. Open a [new issue](https://github.com/r02pro/r02pro_source/issues/new/choose).
2. Fill in the template: which chapter and section, a quote of the problematic text or code, what is wrong, and (if you have one) a suggested fix.

Issues the author labels `accepted` count as contributions.

## What happens next

The author reviews contributions on a rolling basis. Merged pull requests and accepted issues are added to `contributors.csv`, which automatically places your name and GitHub handle in the book's acknowledgments at the next build.
